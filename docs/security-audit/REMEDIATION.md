## Validation

The final backend gate passed all seven fixes: 1,364 tests and 8,621 assertions, plus Pint, PHPStan, deptrac and OpenAPI drift checks (`DB_PORT=15433 DB_DATABASE=prs_test COMPOSER_PROCESS_TIMEOUT=0 composer gate`). The standalone audit retest passed 11 cases/66 assertions on final code. Frontend API drift checks, lint, formatting and type checking passed; final client regeneration and API drift checks passed without further generated changes. The complete frontend unit suite passed 684 tests in 121 files with one worker and a 60-second test timeout. The full serial browser run completed with 176 passes and four failures: Arabic Catalog detail timed out, Course and Cycle collection checks timed out, and Dean collection accessibility scanning lost its page context during navigation. All four passed in a targeted traced retest with their original assertions and timeouts (4 passed in 2.9 minutes). The original failures and their contexts remain in evidence. After reseeding only native `prs_test`, the complete Admissions journey passed on final code: a stranger applies and is admitted as a Student across every role (1 passed in 6.3 minutes). The full browser run was not repeated after the targeted retests; the results are 176 original passes plus four successful failure retests, with the affected Admissions flow checked again separately. An additional stage-authorization finding (AUDIT-07) was confirmed during review, fixed, and passed the rollback-only HTTP-kernel retest; its eight EN/AR Feature regressions passed (40 assertions) on an isolated PostgreSQL 18 cluster, and the complete fresh backend gate passed there. Composer’s default 300-second process timeout interrupted the first full backend gate; the final run disables that timeout. The initial frontend unit run hit two UI timeouts and one worker startup timeout while host RAM/swap were exhausted (677 tests passed). Both affected files passed on a one-worker retest (7 tests); a later one-worker run hit another 20-second UI timeout (that case passed in the original full run). Final verification uses one worker and a 60-second test timeout to accommodate host contention. No assertions or application behavior were changed for those timing failures. Narrow regression runs passed, including 294 Admissions/authentication tests before the additional contention regression and 11 AuthTest cases afterward. Post-update Composer and npm advisory scans both report zero vulnerabilities; their JSON outputs are preserved. The Orval retest reports `triggered: false`. Red/green runs are preserved alongside the original exploits.

The first browser attempt was stopped after four passing tests when overlapping browser/unit work exhausted host memory; the database was reseeded for a fresh browser-only run. Backend and browser tests initially ran serially against native `prs_test`. For the final backend run, a user-owned temporary PostgreSQL 18 cluster uses loopback port 15433, with the same en_US.UTF-8 database locale; Playwright remains on native port 5432. Both database names are `prs_test`, with separate data directories and records. The temporary cluster was stopped and removed after backend verification. The running `prs` database and existing development servers are preserved. Browser validation uses independent API/web ports 18051/15173; the native disposable database is reseeded only between browser runs.

## Scope and remaining accepted limits

[ADR-0051](../adr/0051-security-audit-remediation.md) amends ADR-0005 only for these controls. Email delivery, the mock email verification link, stronger passwords, malware scanning, TLS deployment, MFA and remaining production infrastructure stay deferred under the accepted localhost learning scope. Public issued-Transcript capability links remain intentional under ADR-0046/0047. This remediation is not production certification.

The login locks and rate counters require a shared cache across serving workers; the repository default is the PostgreSQL database cache. A contender receives 429 with a one-second retry, avoiding queued password checks. The 30-second lock lease bounds cleanup after a killed worker.

Independent specification and standards reviews found no remaining actionable findings after the login race fix; the additional stage guard also passed specification review. The concurrency test cleanup also covers connection/transaction setup failures after fork.
