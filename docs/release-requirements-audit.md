# Release requirements audit

Audited 2026-09-28 against `main` at `44807f61223dbbebca8551c0f8844cb6fd24db78` after the seven numbered phases.

This is a source inspection, not fresh test execution or human acceptance. “Implemented” means an executable route, owning implementation, frontend surface, and nearby regression coverage were located; it does not certify every acceptance criterion or prove the current gates pass. No backend gate, frontend gate, browser journey, load test, or external security assessment was run by this audit. Current release verification belongs in the [release-readiness record](release-readiness.md); [new local tickets](../.scratch/release-readiness/spec.md) track these findings.

The [SRS](SRS.md) and [82 business requirements](business-requirements.md) define the baseline; accepted [ADRs](adr/) amend it. [ADR-0005](adr/0005-localhost-learning-build.md) deliberately limits this release to localhost domain workflows. The [codebase map](agents/codebase-map.md) and [glossary](../CONTEXT.md) locate ownership and canonical terminology. The following matrix covers every numbered BR by group, and every functional SRS family. A mixed row records its unfulfilled criteria separately below.

Status terms: **Implemented** = source-supported localhost capability; **Missing localhost** = retained capability absent from executable surfaces; **Deferred** = documented scope exclusion; **Unresolved** = baseline and executable behaviour need reconciliation or narrower acceptance evidence.

## Remaining retained localhost work

1. **Runtime Role assignment.** User model assignment methods and seeded Roles exist, but [Identity routes](../backend/modules/Identity/Public/Http/routes.php) expose no admin User Role mutation, and [app routes](../frontend/src/app/App.tsx) expose no such management screen. [ADR-0008](adr/0008-rbac-enums-static-matrix.md) explicitly retains editable assignments restricted to R09/R10. A vertical implementation ticket should include admin API, multi-Role EN/AR UI, audit, authorization and regression coverage. Fixed permission definitions remain in code.
2. **Remaining Phase-4.6 capabilities.** [Roadmap](ROADMAP.md) retains the missing report families, attendance reporting, richer cards, global search, column selection, remaining collection filtering/export and Course bulk import. Attendance reporting/global search/column selection are roadmap capabilities, not separate numbered FR-RPT report rows. Course XLSX export already exists; do not re-ticket it as wholly absent.
3. **Human acceptance.** Existing browser suites establish inspection evidence only. Complete seeded-persona acceptance, permissions, EN/AR, RTL, transcript verification and printing before a localhost release claim. Automated accessibility assertions are narrower than complete WCAG conformance.

## Unresolved acceptance and wording details

- **Program listing metadata (FR-ADM-004.2).** Names, degree, hierarchy and CH exist in Catalog; [ProgramStep](../frontend/src/features/admissions/wizard/ProgramStep.tsx) shows names/degree and hierarchy but omits the available total_required_ch. Program descriptions, admission summaries and specializations are absent from [ProgramResource](../backend/modules/Catalog/Internal/Http/Resources/ProgramResource.php). No inspected accepted ADR explicitly defers them. Determine whether they belong in retained localhost admission acceptance, or amend the requirement with an explicit decision. The [glossary](../CONTEXT.md) warns against “track” as a synonym for Program; adding an unmodeled track entity requires a domain decision.
- **Single-use verification (FR-ADM-002.5).** [EmailVerificationController](../backend/modules/Admissions/Internal/Http/Controllers/EmailVerificationController.php) and [EmailVerificationTest](../backend/tests/Feature/Admissions/EmailVerificationTest.php) explicitly accept idempotent re-clicks. Signed expiry and resend throttling exist; a consumed-token invariant does not. Clarify whether one effective verification transition is sufficient, or the signed link must become invalid after use.
- **Security Audit Log completeness (FR-SEC-002.10).** [Calendar writes](../backend/modules/Calendar/Internal/Http/Controllers/SemesterController.php) have no AuditLogger invocation; [Catalog history](adr/0011-catalog-version-snapshots.md) is deliberately separate. Auth, exports, overrides, credit decisions and Records actions provide useful audit coverage, but “all sensitive CRUD” remains broader. Scope and enumerate retained audited mutations before declaring that criterion complete. Seven-year operational retention remains deferred.
- **Retake wording.** [GpaCalculator](../backend/modules/Grading/Internal/Support/GpaCalculator.php) selects the latest finalized counted Attempt unconditionally, including a worse Retake (BR-53). [BR-55/58/61](business-requirements.md) and [ADR-0038](adr/0038-termination-uses-effective-grades.md) use “successful” later Attempt when describing clearance. Distinguish superseding a Grade from clearing a failure/termination trigger, and explicitly test a D/F followed by C or D+ if that scenario is a concern. This audit identifies wording to reconcile; it does not establish an implementation defect.
- **Fine UI acceptance.** Upload percentage progress, every responsive breakpoint and latest-two browser versions were not verified by this source audit. [DocumentsStep](../frontend/src/features/admissions/wizard/DocumentsStep.tsx) has upload workflow state; targeted browser acceptance should establish the claimed presentation before treating every FR-ADM-003 criterion as passed.
- **Notification exhaustiveness.** [NotificationType](../backend/modules/Notifications/Public/Enums/NotificationType.php) defines selected event types; “all system events” (BR-71) should mean a reviewed list of required user-facing events, rather than literally every CRUD/event. Domain transitions, Security Audit Log and in-app Notifications serve distinct purposes.
